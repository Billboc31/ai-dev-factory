# T014 — Stabiliser le validator planner flexible

## Contexte

Le validator planner actuel dans `tools/agent_runner/run_step.py` est encore trop fragile.

Avant, le système validait uniquement des sections exactes :

```text
## contexte
## objectif
## inclus
## hors scope
## critères d'acceptation
```

Problème : les LLM produisent souvent des variantes, synonymes, pluriels, formulations anglaises ou titres légèrement différents.

Résultat : des plans valides étaient rejetés.

Le projet a déjà introduit le concept de validation souple via `_REQUIRED_SECTION_GROUPS`, mais il faut maintenant vérifier que la migration est complète, stabiliser la logique et tester réellement le workflow planner.

---

## Objectif

Rendre la validation planner robuste et réellement utilisable en runtime réel.

Le validator doit :

- accepter des synonymes raisonnables
- rester strict sur la structure minimale
- continuer à détecter les faux plans
- éviter les outputs déguisés en implémentation terminée

Le workflow doit ensuite être testé de bout en bout pour confirmer que :

```text
INIT
→ planner
→ PLAN_REVIEW_NEEDED
```

fonctionne correctement.

---

## Inclus

### Validator planner

Vérifier dans `run_step.py` :

- suppression de l’ancien `_REQUIRED_SECTIONS`
- utilisation de `_REQUIRED_SECTION_GROUPS`
- validation par groupes de synonymes
- conservation :
  - minimum word count
  - forbidden phrases
  - détection faux outputs

### Import subprocess

Vérifier le fix :

```python
import subprocess
```

et absence de :

```python
import subprocessf
```

### Runtime logs

Vérifier que les logs runtime restent explicites.

### Test runtime réel

Tester :

- un plan valide avec synonymes
- un plan invalide
- transition workflow complète

## Critères d’acceptation

### Validator flexible

Le validator accepte par exemple :

```text
## contexte technique
## objectifs
## scope
## non inclus
## acceptance criteria
```

sans rejet.

### Validator strict sur le fond

Le validator continue à rejeter :

- plans trop courts
- outputs déguisés
- “implémentation terminée”
- faux résumés

### Workflow fonctionnel

Exécution réelle valide :

```text
INIT
→ PLAN_REVIEW_NEEDED
```

sans erreur.

### Aucun impact architecture

Le système reste :

- déterministe
- explicite
- reviewable
- Git-native
